  1. 01

    Make the wrong thing hard to do

    A convention nobody can violate beats a convention everyone agrees with. Constraints that live in the type system, the query layer, or the build pipeline keep working when the team is tired.

  2. 02

    Read the query plan before arguing about the abstraction

    Most performance debates are really debates about measurements nobody took. The database will tell you what is slow if you ask it directly.

  3. 03

    Write it down while the reasoning is still recoverable

    An architecture decision record costs twenty minutes and saves the next engineer a week of archaeology. The value is not the decision — it is the constraint that forced it.

  4. 04

    Delete code before adding a flag

    Every configuration branch doubles the surface you have to test. Most features are not optional; they are just unloved, and the honest move is removal.

  5. 05

    Optimise for the second year

    Shipping is the easy part. Almost everything that makes a system expensive later was a reasonable decision made in the first month.

  6. 06

    Leave the codebase friendlier than you found it

    Not a rewrite. One clearer name, one test that was missing, one comment that explains why rather than what.
